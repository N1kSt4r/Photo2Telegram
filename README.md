# Photo2Telegram

Локальное приложение для подготовки серии постов в Telegram из фотографий и видео. Помогает просмотреть съёмку по хронологии, скрыть лишнее, собрать посты до 10 файлов, выбрать порядок вложений и написать подписи.

Интерфейс работает в браузере, небольшой Python-сервер читает файлы на компьютере. Медиа никуда не загружаются. Оригиналы не изменяются: при экспорте создаются их копии без конвертации. Отправка в Telegram выполняется вручную.

## Возможности

- Лента по дням с миниатюрами, датой и временем, фильтром неиспользованных файлов.
- Крупный просмотр фото и воспроизведение видео, навигация с клавиатуры.
- Кадры-превью и длительность видео с кэшированием.
- Панель текущего поста с перестановкой вложений перетаскиванием.
- Автосохранение черновиков, подписей, порядка постов и скрытых файлов.
- Экспорт каждого поста в отдельную пронумерованную папку.

## Требования

- **macOS, Windows или Linux** с графическим окружением. Для открытия файлов и папок на Linux нужен `xdg-open`.
- **Python 3.10+** с `pip` и модулем `venv`. На Linux модуль `venv` иногда устанавливается отдельно средствами дистрибутива.
- Современный браузер.
- **FFmpeg и FFprobe** для превью и длительности видео. Без них ролики можно выбирать и экспортировать, но вместо кадров будут заглушки. Воспроизведение зависит от поддержки кодека браузером; есть кнопка открытия в системном плеере.

## Быстрый запуск

Склонируйте репозиторий и запустите приложение, указав существующую папку со своими фотографиями и видео:

```sh
git clone https://github.com/N1kSt4r/Photo2Telegram.git
cd Photo2Telegram
bash run.sh "$HOME/path/to/photos"
```

На Windows после клонирования запустите из PowerShell:

```powershell
.\run.bat "$HOME\path\to\photos"
```

Замените `"$HOME/path/to/photos"` на свой путь. Пробелы в пути поддерживаются — оставьте кавычки. Сервер читает только непосредственное содержимое папки, без вложенных каталогов. Скрипт проверит Python, создаст `.venv` в корне репозитория, установит зависимости из `requirements.txt` и откроет браузер. Интернет нужен при первой установке и изменении зависимостей. Повторный запуск использует готовое окружение. Без аргументов он покажет подсказку.

Обычно адрес — **http://127.0.0.1:8765**. Если порт занят, сервер выберет следующий и напечатает адрес в Terminal. Держите Terminal открытым во время работы; для остановки нажмите **Ctrl+C**.

Скрипт можно вызывать из другой рабочей папки: путь к приложению определяется по расположению `run.sh`, а относительный путь к медиа — относительно текущей рабочей папки.

### Несколько съёмок

Для каждой отдельной библиотеки задавайте свою папку данных через `--data`, чтобы черновики не смешивались:

```sh
bash run.sh "$HOME/path/to/photos" --data .local/my-project --port 8765
```

При следующем запуске этой съёмки используйте те же пути. Каталог `.local/` исключён из Git.

| Аргумент | Назначение | По умолчанию |
| --- | --- | --- |
| Первый аргумент | Существующая папка исходных фото и видео | Обязателен |
| `--data` | Черновики, кэш и служебные файлы | `data/` в корне репозитория |
| `--port` | Начальный порт; проверяются он и следующие 19 | `8765` |

Сервер доступен только на этом компьютере через `127.0.0.1`.

## Как подготовить посты

1. Откройте вкладку **«Фото и видео»**. При необходимости выберите день или включите **«Только неиспользованные»**.
2. Нажмите на миниатюру для крупного просмотра. Кнопка **«+»** в ленте или **«В текущий пост»** в просмотре добавляет файл в пост.
3. Справа виден выбранный набор. Перетащите миниатюры в нужном порядке; крестик убирает файл из поста. Фото и видео делят общий лимит **10 файлов**.
4. Задайте название для себя и необязательную подпись. Название используется для папки экспорта. Подписи длиннее **1024 символов** нужно сократить перед экспортом — это ограничение приложения.
5. Нажмите **«Готово, следующий пост»** и продолжайте отбор с текущего места.
6. Во вкладке **«Посты»** просмотрите всю серию. **«Открыть»** выбирает пост для редактирования, стрелки **↑ / ↓** меняют порядок постов, крестик удаляет черновик.
7. Дождитесь статуса **«Сохранено на диске»** перед закрытием страницы.

Кнопка **«Скрыть»** убирает файл из основной ленты. Он остаётся на диске и во всех постах, куда уже добавлен. Вернуть его можно во вкладке **«Скрытые»**. Использованные файлы помечаются номером поста; один файл можно добавить в несколько постов.

### Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `←` / `→` | Предыдущий / следующий файл в крупном просмотре |
| `Пробел` | Добавить текущий файл в пост или убрать его |
| `H` | Скрыть / вернуть текущий файл |
| `Esc` | Закрыть крупный просмотр |
| `Alt` + `←` / `→` | Переставить миниатюру поста, выбранную клавишей `Tab` |

При вводе текста эти сочетания не перехватываются. Если фокус находится на видеоплеере, клавиши управляют плеером; используйте кнопку выбора файла под ним.

## Экспорт и отправка

Кнопка **«Экспортировать посты»** экспортирует все непустые посты в порядке вкладки **«Посты»**, включая текущий незавершённый черновик. В исходной папке создаётся каталог **«Посты для Telegram»**, а внутри — отдельный каталог каждого экспорта:

```text
Посты для Telegram/
└── 2025-01-03 16-43-05-3238/
    ├── 001 — Пост 1/
    │   ├── 01 — 2025-01-01 07-51-56.HEIC
    │   ├── 02 — 2025-01-02 14-02-37.MOV
    │   └── Подпись.txt
    ├── 002 — Пост 2/
    │   └── 01 — 2025-01-02 10-09-28.HEIC
    ├── Порядок постов.json
    └── Как отправить.txt
```

Файлы копируются **без конвертации и изменения содержимого**: HEIC остаётся HEIC, MOV — MOV. Номера в начале имён копий обозначают выбранный порядок. `Подпись.txt` создаётся только при наличии текста; пустые строки и пробелы не создают файл.

Каждый экспорт создаёт новый каталог и требует места под копии выбранных файлов. Предыдущие экспорты и черновики сохраняются.

После завершения нажмите **«Открыть папку»**. В Telegram выберите медиа из папки одного поста, вставьте текст из `Подпись.txt`, если он есть, и проверьте порядок вложений перед отправкой. Совместимость форматов и способ их отображения зависят от клиента Telegram. Само приложение ничего не публикует.

### Загрузка миниатюр

Загрузка разделена на три пула: до **6 запросов** для видимых миниатюр, до **6** для четырёх соседних рядов сверху и снизу и до **3** для остальных кадров открытой ленты в фоне. Сначала завершается загрузка видимых миниатюр, затем загружаются соседние, и только после них — остальные в фоне. Всего одновременно выполняется не больше 6 запросов, в фоновом режиме — не больше 3. При прокрутке очередь переключается на новые видимые кадры. Ряды определяются по фактической раскладке и пересчитываются при изменении размера окна. Фоновая загрузка постепенно готовит превью, используя браузерный и дисковый кэши; невидимые изображения не декодируются все сразу. На сервере у этих пулов отдельные лимиты обработки; браузер может дополнительно ограничивать число сетевых соединений. При прокрутке следующие запросы выбираются для нового положения ленты, уже начатые завершаются. Уже загруженные миниатюры переиспользуются при выборе файлов и редактировании постов. HTTP-кэш браузера также используется: принудительных повторных загрузок ради заполнения дискового кэша нет. Кэш в памяти страницы ограничен 256 превью; дисковый кэш находится в `data/previews/` и по умолчанию ограничен 2 ГБ.

Крупные фотографии обрабатываются отдельно от очереди миниатюр. При первом просмотре ещё не обработанного HEIC или видео создание превью всё равно может занять время.

В большом просмотре после загрузки открытого фото заранее загружаются до 10 фотографий вперёд и 10 назад по текущему порядку просмотра. Ближайшие кадры загружаются первыми, до трёх одновременно; для открываемого фото на сервере есть дополнительный отдельный слот обработки. Пока окно большого просмотра ожидает крупные превью, новые запросы миниатюр приостановлены; уже начатые завершаются. После заполнения окна предзагрузки или закрытия просмотра миниатюры продолжают загружаться. Видео и недоступные файлы пропускаются. В памяти страницы хранятся сжатые крупные превью текущего окна (до 21 изображения), при перемещении старые освобождаются. Также используется HTTP-кэш браузера. Оригиналы не меняются.

### Управление дисковым кэшем

Кнопка **«Кэш превью»** в правой панели показывает размер дискового кэша и отдельные счётчики миниатюр, крупных превью и данных длительности видео, выбор лимита (512 МБ, 1, 2, 5 или 10 ГБ) и **«Очистить кэш»**. Лимит сохраняется для текущей папки данных и применяется сразу.

При достижении лимита удаляются превью, которые сервер дольше всего не запрашивал. Старые версии после изменения оригинала, превью пропавших файлов и устаревшие форматы кэша удаляются при запуске и обновлении библиотеки. Создаваемые и читаемые файлы защищены от удаления; во время обработки лимит может временно превышаться, затем освобождается место.

Очистка удаляет только сгенерированные превью и метаданные длительности видео. Оригиналы, посты и подписи остаются на месте. Уже показанные изображения могут остаться в памяти страницы и HTTP-кэше браузера, в том числе после перезагрузки. Они не копируются на диск повторно только ради счётчика. В окне кэша отдельно показаны файлы на диске, число миниатюр, загруженных текущей страницей, и количество миниатюр в её быстром кэше. Размер внутреннего HTTP-кэша браузера приложение не измеряет. Длительность видео восстанавливается из каталога при запуске или обновлении библиотеки. Счётчики открытого окна кэша обновляются автоматически. После ручной очистки фоновая подготовка в этой вкладке приостанавливается до перезагрузки страницы, а видимые и соседние превью продолжают загружаться по мере необходимости.

## Форматы и хронология

- Изображения: JPG, JPEG, HEIC, HEIF, PNG, TIF, TIFF, WebP. На всех ОС используется Pillow, а для HEIC/HEIF — плагин pillow-heif. Превью учитывают ориентацию EXIF и цветовой профиль; экспорт сохраняет оригиналы.
- Видео: MOV, MP4, M4V, WebM.
- Расширения распознаются независимо от регистра.
- В первую очередь используется дата из имени вида `2025-01-01 07-51-56.HEIC`.
- Для фото без такой даты читаются метаданные; если дата недоступна, используется время изменения файла.
- Для видео без даты в имени используется время изменения файла. Этот источник даты отмечается в крупном просмотре.

Нажмите **«Обновить библиотеку»**, чтобы увидеть новые файлы без перезапуска сервера. Посты, подписи, скрытые файлы и порядок вложений сохраняются. Сканируется только выбранная папка, без вложенных каталогов.

## Где хранится работа

По умолчанию служебные файлы находятся в `data/`, либо в каталоге, заданном через `--data`:

| Файл / папка | Содержимое |
| --- | --- |
| `project.json` | Посты, подписи, порядок вложений и скрытые файлы |
| `cache-settings.json` | Сохранённый лимит дискового кэша |
| `library.json` | Имена, даты и доступность известных файлов; содержимое файлов не хэшируется |
| `project.backup.json` | Предыдущее сохранение проекта |
| `previews/` | JPEG-превью и длительность видео |
| `instance.lock`, `runtime.json` | Данные работающего экземпляра сервера |

Для резервной копии сохраните `project.json`, `library.json` и исходные медиа. Кэш можно очистить кнопкой **«Кэш превью»** или удалить папку `previews/` при выключенном сервере: нужные превью создадутся заново. Для восстановления предыдущего сохранения остановите сервер, сохраните копию текущего `project.json` и замените его содержимым `project.backup.json`.

Если файл исчез, проект продолжает открываться: файл отмечается как недоступный и сохраняет своё место в постах и список скрытия. Его можно убрать из поста или вернуть под прежним именем в исходную папку и нажать **«Обновить библиотеку»**. Экспорт блокируется только если недоступный файл используется в посте; ошибка перечисляет такие файлы.

Переименования и переносы не отслеживаются. Переименованный файл появляется как новый, а прежняя запись остаётся недоступной. Сопоставление идёт по имени: другой файл под прежним именем также займёт старое место в постах. В старых проектах без `library.json` у уже пропавших файлов может быть неизвестно исходное имя — их записи и подписи всё равно сохранятся.

Используйте одну вкладку для редактирования. При конфликте сохранений обновите отставшую вкладку. Повторный запуск с той же папкой данных использует уже работающий экземпляр; чтобы изменить параметры, сначала остановите его.

## Структура репозитория

```text
Photo2Telegram/
├── README.md              Инструкция
├── .gitignore             Исключения для личных и генерируемых файлов
├── run.sh                 Запуск на macOS / Linux
├── run.bat                Запуск на Windows
├── requirements.txt       Зависимости Python
├── .github/workflows/     Проверки GitHub Actions
├── src/
│   ├── launch.py          Настройка окружения и запуск
│   ├── server.py          Локальный сервер, библиотека и экспорт
│   └── web/               HTML, CSS, JavaScript и SVG-заглушка
├── tests/
│   ├── test_server.py     Проверки серверной части
│   └── fixtures/          Синтетические изображения и видео
└── data/                  Черновики и кэш, исключены из Git
```

`.gitignore` исключает личные фотографии и видео, экспорт, `data/`, `.local/`, кэш Python и служебные файлы macOS. Исключение для `tests/fixtures/` позволяет хранить тестовые медиа в репозитории. Если задаёте другой каталог данных внутри репозитория, добавьте его в `.gitignore`. Исключённые черновики и медиа нужно резервировать отдельно.

## Тесты

После первого запуска приложения используйте Python из его окружения. На macOS/Linux:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

На Windows:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

Для ручной настройки или CI: создайте виртуальное окружение через `python -m venv .venv` и установите `requirements.txt` его интерпретатором через `python -m pip install -r requirements.txt`.

Тесты работают с временными папками и включёнными в репозиторий файлами. Личная медиатека не нужна. Если FFmpeg/FFprobe недоступны, проверка превью и длительности видео пропускается. Проверки сохранения, порядка файлов, смешанных постов и экспорта выполняются без них. Для превью изображений используются одинаковые библиотеки на всех ОС.

В `tests/fixtures/` находятся небольшие синтетические файлы: цветной тестовый рисунок в PNG и HEIC, однотонный JPEG и двухсекундный MOV с движущимся тестовым рисунком. Они созданы специально для этого проекта с помощью генераторов FFmpeg и системного `sips`; личные снимки и сторонние стоковые материалы не использовались.

Чтобы попробовать интерфейс на этих файлах с отдельным проектом:

```sh
bash run.sh tests/fixtures --data .local/demo
```

## GitHub Actions

Workflow `.github/workflows/tests.yml` запускается на push, pull request и вручную. Основная матрица проверяет Windows, macOS и Linux с Python 3.10 и 3.12; отдельная задача Linux устанавливает FFmpeg и проверяет видеопревью. Работа без видеоинструментов проверяется принудительным отключением их в тесте. Секреты и личные медиа не нужны.

Проверки включают HEIC, EXIF, прозрачность, кириллицу и пробелы в путях, сохранение и экспорт, HTTP-сервер и защиту от второго экземпляра. Результаты появятся во вкладке Actions после отправки workflow в GitHub.

Очередь загрузки миниатюр можно проверить отдельно средствами Node.js, без установки npm-пакетов:

```sh
node --test tests/test_preview_loader.cjs
```
