# Photo2Telegram

Локальное приложение для подготовки серии постов в Telegram из фотографий и видео. Помогает просмотреть съёмку по хронологии, скрыть лишнее, собрать посты до 10 файлов, выбрать порядок вложений и написать подписи.

Интерфейс работает в браузере, небольшой Python-сервер читает файлы на компьютере. Подготовка выполняется локально; загрузка в Telegram происходит только по кнопке публикации. Оригиналы не изменяются: при экспорте создаются их копии без конвертации. Можно отправлять экспорт вручную или подключить бота для публикации из приложения.

## Возможности

- Лента по дням с миниатюрами, датой и временем, фильтром неиспользованных файлов.
- Крупный просмотр фото и воспроизведение видео, навигация с клавиатуры.
- Кадры-превью и длительность видео с кэшированием.
- Панель текущего поста с перестановкой вложений перетаскиванием.
- Автосохранение черновиков, подписей, порядка постов и скрытых файлов.
- Экспорт каждого поста в отдельную пронумерованную папку.
- Отправка постов в канал через обычный или самостоятельно запущенный локальный Bot API, с предварительной проверкой и историей результатов.

## Требования

- **macOS, Windows или Linux** с графическим окружением. Для открытия файлов и папок на Linux нужен `xdg-open`.
- **Python 3.10+** с `pip` и модулем `venv`. На Linux модуль `venv` иногда устанавливается отдельно средствами дистрибутива.
- Современный браузер.
- **FFmpeg и FFprobe** для превью и длительности видео. Без них ролики можно выбирать и экспортировать, но вместо кадров будут заглушки. Воспроизведение зависит от поддержки кодека браузером; есть кнопка открытия в системном плеере.

## Быстрый запуск

Склонируйте репозиторий и запустите приложение, указав существующую папку со своими фотографиями и видео:

```sh
git clone https://github.com/N1kSt4r/Photo2Telegram.git
cd Photo2Telegram
bash run.sh "$HOME/path/to/photos"
```

На Windows после клонирования запустите из PowerShell:

```powershell
.\run.bat "$HOME\path\to\photos"
```

Замените `"$HOME/path/to/photos"` на свой путь. Пробелы в пути поддерживаются — оставьте кавычки. Сервер читает только непосредственное содержимое папки, без вложенных каталогов. Скрипт проверит Python, создаст `.venv` в корне репозитория, установит зависимости из `requirements.txt` и откроет браузер. Интернет нужен при первой установке и изменении зависимостей. Повторный запуск использует готовое окружение. Без аргументов открывается текущая рабочая директория. Справка: `bash run.sh --help` или `run.bat --help`.

Обычно адрес — **http://127.0.0.1:8765**. Если порт занят, сервер выберет следующий и напечатает адрес в Terminal. Держите Terminal открытым во время работы; для остановки нажмите **Ctrl+C**.

Скрипт можно вызывать из другой рабочей папки: путь к приложению определяется по расположению `run.sh`, а относительный путь к медиа — относительно текущей рабочей папки.

### Несколько съёмок

Нажмите **«Выбрать папку»** в браузере. Перейдите по каталогам или начните вводить путь: подсказки покажут папки с подходящим началом имени (без учёта регистра). Выбирайте мышью или стрелками и Enter. Можно также ввести путь целиком и нажать **«Перейти»**, затем **«Открыть эту папку»**. Текущий черновик сохраняется перед переключением. Посты, скрытые файлы и кэш хранятся отдельно для каждой папки; при возвращении черновики восстанавливаются. Вложенные каталоги не сканируются автоматически.

Смена папки действует для всего запущенного сервера. В других открытых вкладках нужно обновить страницу; сохранение старого проекта в новую библиотеку блокируется. Во время экспорта переключение недоступно.

При запуске используется переданный путь, а без него — текущая рабочая директория (также для `python3 src/server.py` без `--root`). Можно запустить `bash run.sh` и выбрать папку в браузере.

При необходимости задайте отдельное хранилище через `--data`:

```sh
bash run.sh "$HOME/path/to/photos" --data .local/my-project --port 8765
```

При следующем запуске этой съёмки используйте те же пути. Каталог `.local/` исключён из Git.

| Аргумент | Назначение | По умолчанию |
| --- | --- | --- |
| Первый аргумент | Существующая папка исходных фото и видео | Текущая рабочая директория |
| `--data` | Черновики, кэш и служебные файлы | `data/` в корне репозитория |
| `--port` | Начальный порт; проверяются он и следующие 19 | `8765` |

Сервер доступен только на этом компьютере через `127.0.0.1`.

## Как подготовить посты

1. Откройте вкладку **«Фото и видео»**. При необходимости выберите день или включите **«Только неиспользованные»**.
2. Нажмите на миниатюру для крупного просмотра. Кнопка **«+»** в ленте или **«В текущий пост»** в просмотре добавляет файл в пост.
3. Справа виден выбранный набор. Перетащите миниатюры в нужном порядке; крестик убирает файл из поста. Фото и видео делят общий лимит **10 файлов**.
4. Задайте название для себя и необязательную подпись. Название используется для папки экспорта. Подписи длиннее **1024 символов** нужно сократить перед экспортом — это ограничение приложения.
5. Нажмите **«Готово, следующий пост»** и продолжайте отбор с текущего места.
6. Во вкладке **«Посты»** просмотрите всю серию. **«Открыть»** выбирает пост для редактирования, стрелки **↑ / ↓** меняют порядок постов, крестик удаляет черновик.
7. Дождитесь статуса **«Сохранено на диске»** перед закрытием страницы.

Кнопка **«Скрыть»** убирает файл из основной ленты. Он остаётся на диске и во всех постах, куда уже добавлен. Вернуть его можно во вкладке **«Скрытые»**. Использованные файлы помечаются номером поста; один файл можно добавить в несколько постов.

### Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `←` / `→` | Предыдущий / следующий файл в крупном просмотре |
| `Пробел` | Добавить текущий файл в пост или убрать его |
| `H` | Скрыть / вернуть текущий файл |
| `Esc` | Закрыть крупный просмотр |
| `Alt` + `←` / `→` | Переставить миниатюру поста, выбранную клавишей `Tab` |

При вводе текста эти сочетания не перехватываются. Если фокус находится на видеоплеере, клавиши управляют плеером; используйте кнопку выбора файла под ним.

## Экспорт и отправка

Кнопка **«Экспортировать посты»** экспортирует все непустые посты в порядке вкладки **«Посты»**, включая текущий незавершённый черновик. В исходной папке создаётся каталог **«Посты для Telegram»**, а внутри — отдельный каталог каждого экспорта:

```text
Посты для Telegram/
└── 2025-01-03 16-43-05-3238/
    ├── 001 — Пост 1/
    │   ├── 01 — 2025-01-01 07-51-56.HEIC
    │   ├── 02 — 2025-01-02 14-02-37.MOV
    │   └── Подпись.txt
    ├── 002 — Пост 2/
    │   └── 01 — 2025-01-02 10-09-28.HEIC
    ├── Порядок постов.json
    └── Как отправить.txt
```

Файлы копируются **без конвертации и изменения содержимого**: HEIC остаётся HEIC, MOV — MOV. Номера в начале имён копий обозначают выбранный порядок. `Подпись.txt` создаётся только при наличии текста; пустые строки и пробелы не создают файл.

Каждый экспорт создаёт новый каталог и требует места под копии выбранных файлов. Предыдущие экспорты и черновики сохраняются.

После завершения нажмите **«Открыть папку»**. В Telegram выберите медиа из папки одного поста, вставьте текст из `Подпись.txt`, если он есть, и проверьте порядок вложений перед отправкой. Совместимость форматов и способ их отображения зависят от клиента Telegram. Само приложение ничего не публикует.

### Загрузка миниатюр

Загрузка разделена на три пула: до **6 запросов** для видимых миниатюр, до **6** для четырёх соседних рядов сверху и снизу и до **3** для остальных кадров открытой ленты в фоне. Сначала завершается загрузка видимых миниатюр, затем загружаются соседние, и только после них — остальные в фоне. Всего одновременно выполняется не больше 6 запросов, в фоновом режиме — не больше 3. При прокрутке очередь переключается на новые видимые кадры. Ряды определяются по фактической раскладке и пересчитываются при изменении размера окна. Фоновая загрузка постепенно готовит превью, используя браузерный и дисковый кэши; невидимые изображения не декодируются все сразу. На сервере у этих пулов отдельные лимиты обработки; браузер может дополнительно ограничивать число сетевых соединений. При прокрутке следующие запросы выбираются для нового положения ленты, уже начатые завершаются. Уже загруженные миниатюры переиспользуются при выборе файлов и редактировании постов. HTTP-кэш браузера также используется: принудительных повторных загрузок ради заполнения дискового кэша нет. Кэш в памяти страницы ограничен 256 превью; дисковый кэш находится в `data/previews/` и по умолчанию ограничен 2 ГБ.

Крупные фотографии обрабатываются отдельно от очереди миниатюр. При первом просмотре ещё не обработанного HEIC или видео создание превью всё равно может занять время.

В большом просмотре после загрузки открытого фото заранее загружаются до 10 фотографий вперёд и 10 назад по текущему порядку просмотра. Ближайшие кадры загружаются первыми, до трёх одновременно; для открываемого фото на сервере есть дополнительный отдельный слот обработки. Пока окно большого просмотра ожидает крупные превью, новые запросы миниатюр приостановлены; уже начатые завершаются. После заполнения окна предзагрузки или закрытия просмотра миниатюры продолжают загружаться. Видео и недоступные файлы пропускаются. В памяти страницы хранятся сжатые крупные превью текущего окна (до 21 изображения), при перемещении старые освобождаются. Также используется HTTP-кэш браузера. Оригиналы не меняются.

### Управление дисковым кэшем

Кнопка **«Кэш превью»** в правой панели показывает размер дискового кэша и отдельные счётчики миниатюр, крупных превью и данных длительности видео, выбор лимита (512 МБ, 1, 2, 5 или 10 ГБ) и **«Очистить кэш»**. Лимит сохраняется для текущей папки данных и применяется сразу.

При достижении лимита удаляются превью, которые сервер дольше всего не запрашивал. Старые версии после изменения оригинала, превью пропавших файлов и устаревшие форматы кэша удаляются при запуске и обновлении библиотеки. Создаваемые и читаемые файлы защищены от удаления; во время обработки лимит может временно превышаться, затем освобождается место.

Очистка удаляет только сгенерированные превью и метаданные длительности видео. Оригиналы, посты и подписи остаются на месте. Уже показанные изображения могут остаться в памяти страницы и HTTP-кэше браузера, в том числе после перезагрузки. Они не копируются на диск повторно только ради счётчика. В окне кэша отдельно показаны файлы на диске, число миниатюр, загруженных текущей страницей, и количество миниатюр в её быстром кэше. Размер внутреннего HTTP-кэша браузера приложение не измеряет. Длительность видео восстанавливается из каталога при запуске или обновлении библиотеки. Счётчики открытого окна кэша обновляются автоматически. После ручной очистки фоновая подготовка в этой вкладке приостанавливается до перезагрузки страницы, а видимые и соседние превью продолжают загружаться по мере необходимости.

## Форматы и хронология

- Изображения: JPG, JPEG, HEIC, HEIF, PNG, TIF, TIFF, WebP. На всех ОС используется Pillow, а для HEIC/HEIF — плагин pillow-heif. Превью учитывают ориентацию EXIF и цветовой профиль; экспорт сохраняет оригиналы.
- Видео: MOV, MP4, M4V, WebM.
- Расширения распознаются независимо от регистра.
- В первую очередь используется дата из имени вида `2025-01-01 07-51-56.HEIC`.
- Для фото без такой даты читаются метаданные; если дата недоступна, используется время изменения файла.
- Для видео без даты в имени используется время изменения файла. Этот источник даты отмечается в крупном просмотре.

Нажмите **«Обновить библиотеку»**, чтобы увидеть новые файлы без перезапуска сервера. Посты, подписи, скрытые файлы и порядок вложений сохраняются. Сканируется только выбранная папка, без вложенных каталогов.

## Где хранится работа

По умолчанию служебные файлы находятся в `data/`, либо в каталоге, заданном через `--data`:

| Файл / папка | Содержимое |
| --- | --- |
| `project.json` | Посты, подписи, порядок вложений и скрытые файлы |
| `cache-settings.json` | Сохранённый лимит дискового кэша |
| `library.json` | Имена, даты и доступность известных файлов; содержимое файлов не хэшируется |
| `project.backup.json` | Предыдущее сохранение проекта |
| `previews/` | JPEG-превью и длительность видео |
| `instance.lock`, `runtime.json` | Данные работающего экземпляра сервера |

Первая открытая папка использует существующие файлы в `data/`, без переноса черновиков. Связь папок с проектами хранится в `data/folders.json`; следующие проекты находятся в `data/projects/<идентификатор>/`. При переименовании самой папки она считается новой библиотекой. Для резервной копии всех проектов сохраните всё хранилище `data/` и исходные медиа.

Для резервной копии сохраните `project.json`, `library.json` и исходные медиа. Кэш можно очистить кнопкой **«Кэш превью»** или удалить папку `previews/` при выключенном сервере: нужные превью создадутся заново. Для восстановления предыдущего сохранения остановите сервер, сохраните копию текущего `project.json` и замените его содержимым `project.backup.json`.

Если файл исчез, проект продолжает открываться: файл отмечается как недоступный и сохраняет своё место в постах и список скрытия. Его можно убрать из поста или вернуть под прежним именем в исходную папку и нажать **«Обновить библиотеку»**. Экспорт блокируется только если недоступный файл используется в посте; ошибка перечисляет такие файлы.

Переименования и переносы не отслеживаются. Переименованный файл появляется как новый, а прежняя запись остаётся недоступной. Сопоставление идёт по имени: другой файл под прежним именем также займёт старое место в постах. В старых проектах без `library.json` у уже пропавших файлов может быть неизвестно исходное имя — их записи и подписи всё равно сохранятся.

Используйте одну вкладку для редактирования. При конфликте сохранений обновите отставшую вкладку. Повторный запуск с той же папкой данных использует уже работающий экземпляр; чтобы изменить параметры, сначала остановите его.

## Структура репозитория

```text
Photo2Telegram/
├── README.md              Инструкция
├── .gitignore             Исключения для личных и генерируемых файлов
├── run.sh                 Запуск на macOS / Linux
├── run.bat                Запуск на Windows
├── requirements.txt       Зависимости Python
├── .github/workflows/     Проверки GitHub Actions
├── src/
│   ├── launch.py          Настройка окружения и запуск
│   ├── server.py          Локальный сервер, библиотека и экспорт
│   └── web/               HTML, CSS, JavaScript и SVG-заглушка
├── tests/
│   ├── test_server.py     Проверки серверной части
│   └── fixtures/          Синтетические изображения и видео
└── data/                  Черновики и кэш, исключены из Git
```

`.gitignore` исключает личные фотографии и видео, экспорт, `data/`, `.local/`, кэш Python и служебные файлы macOS. Исключение для `tests/fixtures/` позволяет хранить тестовые медиа в репозитории. Если задаёте другой каталог данных внутри репозитория, добавьте его в `.gitignore`. Исключённые черновики и медиа нужно резервировать отдельно.

## Тесты

После первого запуска приложения используйте Python из его окружения. На macOS/Linux:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

На Windows:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

Для ручной настройки или CI: создайте виртуальное окружение через `python -m venv .venv` и установите `requirements.txt` его интерпретатором через `python -m pip install -r requirements.txt`.

Тесты работают с временными папками и включёнными в репозиторий файлами. Личная медиатека не нужна. Если FFmpeg/FFprobe недоступны, проверка превью и длительности видео пропускается. Проверки сохранения, порядка файлов, смешанных постов и экспорта выполняются без них. Для превью изображений используются одинаковые библиотеки на всех ОС.

В `tests/fixtures/` находятся небольшие синтетические файлы: цветной тестовый рисунок в PNG и HEIC, однотонный JPEG и двухсекундный MOV с движущимся тестовым рисунком. Они созданы специально для этого проекта с помощью генераторов FFmpeg и системного `sips`; личные снимки и сторонние стоковые материалы не использовались.

Чтобы попробовать интерфейс на этих файлах с отдельным проектом:

```sh
bash run.sh tests/fixtures --data .local/demo
```

## Отправка в Telegram (необязательно)

В правой панели нажмите **«Отправить в Telegram»**. Для разработки и тестов настоящие реквизиты не нужны; автоматические проверки используют имитатор API.

Подготовьте:

- **Токен бота**, созданного через [@BotFather](https://t.me/BotFather). Введите его в поле «Токен бота» локально в браузере; не публикуйте его в репозитории. Пустое поле при повторном сохранении оставляет прежний токен.
- **Канал:** публичное `@имя_канала` или числовой ID приватного канала вида `-1001234567890`. Пригласительная ссылка вместо ID не подходит. ID можно получить из `channel_post.chat.id` обновлений бота после публикации тестового сообщения в канале через Telegram ([getUpdates](https://core.telegram.org/bots/api#getupdates)).
- Бота нужно добавить **администратором канала с правом публикации сообщений**.

Выберите режим, сохраните настройки и нажмите **«Проверить подключение»**. Проверка вызывает только `getMe`, `getChat`, `getChatMember` и ничего не публикует. Настройки отдельные для каждой папки с медиа.

### Обычный и локальный Bot API

По умолчанию используется `https://api.telegram.org`. Лимит видео — 50 МБ. Фото приложение готовит в JPEG с качеством 95 и цветовой детализацией 4:2:0, уменьшая до 2560 пикселей по длинной стороне. Маленькие фотографии не увеличиваются. Если результат превышает 10 МБ, подготовка показывает ошибку; качество дополнительно не снижается. Очень вытянутые фото (соотношение больше 20:1) отклоняются до публикации.

Для видео до 2000 МБ выберите **«Локальный · свой сервер»** и укажите базовый адрес, например `http://127.0.0.1:8081`, без `/bot…` и токена. Сервер должен быть запущен с `--local`; выбор режима в приложении сам по себе не меняет конфигурацию Bot API. Адрес относится к компьютеру, на котором работает Python-сервер Photo2Telegram.

Локальный Bot API запускается отдельно от Photo2Telegram. Можно использовать контейнер по инструкции ниже или собрать сервер по [официальной инструкции](https://github.com/tdlib/telegram-bot-api#usage).

В обоих режимах Photo2Telegram передаёт файлы потоковым HTTP-запросом, без загрузки целого видео в оперативную память. Поэтому локальному API не нужен доступ к исходным папкам, в том числе при запуске в Docker. Большой лимит не отменяет требований Telegram к форматам и частоте отправки. Счётчик «Передано Bot API» показывает передачу в локальный контейнер; после неё сервер ещё загружает файлы в Telegram.

### Локальный Bot API через Docker

В репозитории есть [compose.yaml](compose.yaml) для macOS, Linux и Windows. В контейнере работает только Bot API; Photo2Telegram запускается обычным способом. Используется сторонняя сборка [aiogram/telegram-bot-api](https://github.com/aiogram/telegram-bot-api) официального сервера Telegram, версия `10.3`. Docker выбирает вариант AMD64 или ARM64 автоматически, в том числе на Apple Silicon.

Для локального Bot API нужен работающий Docker с Docker Compose и поддержкой Linux-контейнеров.

1. Получите собственные `api_id` и `api_hash` в **API development tools** на [my.telegram.org](https://core.telegram.org/api/obtaining_api_id). Это параметры приложения Telegram, а не токен бота.
2. В настройках Telegram выберите локальный режим, введите **App api_id** и **App api_hash**, затем нажмите **«Сохранить ключи Bot API»**. Они сохраняются в `.env` в корне репозитория; пустые поля оставляют прежние значения. Затем нажмите **«Запустить Bot API»**. После изменения ключей нажмите **«Применить ключи и запустить Bot API»** — работающий контейнер будет пересоздан с сохранением данных.

При настройке из терминала можно скопировать [.env.example](.env.example) в `.env` и заполнить `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`. Не заменяйте уже существующий `.env`: в нём также могут быть сохранённые токены ботов.

Все следующие команды выполняйте из корня репозитория. Проверка конфигурации не выводит значения ключей:

```sh
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=50 telegram-bot-api
```

Без заполненных ключей Compose остановится с сообщением об отсутствующем параметре. Первый запуск скачает образ. Контейнер запускает сервер с `--local`; адрес на компьютере — `http://127.0.0.1:8081`. Порт не открыт для других компьютеров. Если порт 8081 занят, замените в `compose.yaml` левый номер порта, например на `127.0.0.1:8082:8081`, и укажите порт 8082 в Photo2Telegram.

**Переход существующего бота.** Если бот использовался через `api.telegram.org`, остановите отправку и другие программы, работающие с ним, затем один раз вызовите облачный метод [logOut](https://core.telegram.org/bots/api#logout). Следующая команда спросит токен без отображения ввода, ничего не публикует и выводит только результат. На Windows используйте `python` вместо `python3`:

```sh
python3 -c 'import getpass,json,urllib.request; token=getpass.getpass("Bot token: "); request=urllib.request.Request("https://api.telegram.org/bot"+token+"/logOut", data=b"", method="POST"); response=json.load(urllib.request.urlopen(request, timeout=30)); print("logOut:", response.get("ok") is True and response.get("result") is True)'
```

После `logOut: True` локальный сервер можно использовать сразу. Обратно в облачный API Telegram не разрешает войти в течение 10 минут. Выполнять `logOut` при каждом запуске контейнера не нужно.

В Photo2Telegram откройте настройки Telegram, выберите **«Локальный · свой сервер»**, введите `http://127.0.0.1:8081`, сохраните и нажмите **«Проверить подключение»**. Существующие токен бота и канал остаются прежними. Успешная проверка подтверждает подключение и права на канал, ничего не публикуя. Затем можно готовить и отправлять посты.

В локальном режиме в настройках Photo2Telegram доступны **«Запустить Bot API»** и **«Остановить Bot API»**, а также статус контейнера. Они управляют только сервисом из `compose.yaml` этого проекта; Docker должен уже работать, а `.env` — быть заполнен. Первый запуск может скачивать образ. Остановка сохраняет данные и не закрывает Docker Desktop. Во время подготовки или отправки управление заблокировано; сначала остановите очередь и дождитесь завершения текущей операции. Эти кнопки не выполняют переход бота через `logOut` и не изменяют адрес подключения. Для сервера на другом компьютере используйте его собственные средства управления.

Управление контейнером из терминала:

```sh
# Остановить сервер, сохранив данные
docker compose stop

# Запустить снова
docker compose up -d

# Удалить контейнер и сеть, сохранив данные
docker compose down
```

Данные Bot API хранятся в Docker volume `photo2telegram_telegram-bot-api-data`, отдельно от черновиков и кэша Photo2Telegram. Не добавляйте `--volumes` / `-v` к `docker compose down`, если хотите сохранить эти данные. Остановка контейнера не завершает текущую отправку корректно: сначала остановите очередь в приложении и дождитесь окончания текущего поста.

Для обновления измените версию образа в `compose.yaml`, выполните `docker compose pull`, затем `docker compose up -d`. Пока идёт отправка, контейнер и Docker должны работать. Политика `unless-stopped` перезапускает контейнер после запуска Docker, если вы не остановили его вручную. Docker Desktop запускается отдельно от Photo2Telegram.

### Подготовка и публикация

1. Нажмите **«Подготовить текущий пост»** или **«Подготовить все неотправленные»**. Приложение параллельно проверит канал и подготовит файлы (до 12 одновременно). Ошибка подключения не мешает обработке файлов; проверку подключения можно повторить отдельно. Ничего ещё не отправляется в канал.
2. Проверьте название и ID канала, бота, порядок постов, подписи и список файлов. Фото отправляются как JPEG; при необходимости видео преобразуются в MP4/H.264/AAC через FFmpeg. Без FFmpeg используются готовые MP4, а видео, требующие преобразования, блокируют подготовку. Совместимость MP4 дополнительно проверяется при наличии FFprobe. Крупные видео автоматически не ужимаются до лимита.
3. Нажмите **«Отправить выбранные готовые»** или **«Отправить готовые по порядку»**. Изменения текста, порядка и удаление вложений учитываются без повторного преобразования файлов. Новые или изменённые исходники требуют подготовки. Во время отправки выбранная версия фиксируется.

Посты отправляются последовательно: 2–10 фото/видео — альбомом с подписью к первому вложению, один файл — отдельным сообщением, текст без файлов — текстовым сообщением. Лимит подписи — 1024 символа, текста без вложений — 4096; проверка консервативно учитывает эмодзи как две UTF-16 единицы. «Без звука» отключает звук уведомлений. При ограничении частоты Telegram очередь ждёт указанный `retry_after` и делает до трёх повторов.

Закрытие окна настроек или вкладки не останавливает очередь, пока работает Python-сервер. Кнопка остановки завершает текущую отправку и не начинает следующую; остановка подготовки сохраняет полностью готовые посты и кэш файлов. Во время активной обработки или отправки переключение папки и изменение настроек отправки заблокированы. Компьютер должен оставаться включённым и подключённым к интернету.

### Результаты и повторная отправка

История хранит результаты и ссылки на сообщения. Уже отправленные посты пропускаются для той же пары «бот + канал», даже если после отправки изменена подпись; редактирование опубликованных сообщений пока не поддерживается. Для новой публикации создайте новый пост.

Если связь оборвалась после запроса или приложение остановилось во время отправки, результат отмечается как **неизвестный**. Автоматического повтора нет: проверьте канал и выберите **«Пост есть в канале»** либо **«Проверил: поста нет»**. Второй вариант разрешает повтор готового поста, но сам ничего не отправляет. Обычная подтверждённая ошибка Telegram также останавливает очередь; после исправления можно продолжить отправку без новой подготовки.

Токены ботов и ключи локального Bot API хранятся в открытом виде в `.env` в корне репозитория, исключённом из Git; при записи через приложение на macOS/Linux файл доступен только владельцу. Токены остаются отдельными для каждой папки с медиа: приложение создаёт для них переменные `TELEGRAM_BOT_TOKEN_<идентификатор>`. Существующий токен автоматически переносится из `telegram-settings.json` при открытии папки. Канал, режим и ссылка на запись токена остаются в `telegram-settings.json` внутри папки данных проекта. Секреты не возвращаются в браузер: поля показывают только «сохранён локально». Сохраняйте `.env` вместе с резервной копией данных. Журнал `telegram-sent.json` нужно сохранять вместе с черновиками: его удаление уберёт защиту от повторной публикации. Обе записи находятся в исключённом из Git хранилище `data/` (или вашем `--data`). Временные копии в `telegram-outbox/` очищаются после отправки, отмены или ошибки; после аварийного завершения — при следующем открытии проекта. Они не относятся к кэшу превью и требуют дополнительного места на диске.

## GitHub Actions

Workflow `.github/workflows/tests.yml` запускается на push, pull request и вручную. Основная матрица проверяет Windows, macOS и Linux с Python 3.10 и 3.12; отдельная задача Linux устанавливает FFmpeg и проверяет видеопревью. Работа без видеоинструментов проверяется принудительным отключением их в тесте. Секреты и личные медиа не нужны.

Проверки включают HEIC, EXIF, прозрачность, кириллицу и пробелы в путях, сохранение и экспорт, HTTP-сервер и защиту от второго экземпляра. Результаты появятся во вкладке Actions после отправки workflow в GitHub.

Очередь загрузки миниатюр можно проверить отдельно средствами Node.js, без установки npm-пакетов:

```sh
node --test tests/test_preview_loader.cjs
```

При подготовке Telegram каждый пост проверяется отдельно: ошибка в одном не мешает
подготовке следующих. В списке результатов можно отметить готовые посты и нажать
«Отправить выбранные готовые» либо отправить все готовые до первой ошибки.
Посты после ошибки по умолчанию не отмечены; их можно выбрать явно.
При ошибке во время публикации очередь останавливается. Оставшиеся готовые посты
можно отправить без повторной подготовки; подтверждённые публикации пропускаются.
Если результат отправки неизвестен, сначала проверьте канал и отметьте результат в карточке поста.

Подготовка для Telegram выполняется параллельно: до 12 файлов в общей очереди для фото и видео,
в том числе из разных постов. Порядок публикации сохраняется. Успешная проверка
канала используется повторно до минуты при неизменных настройках; кнопка проверки
подключения всегда выполняет свежий запрос.

Готовые файлы для Telegram хранятся на диске в `data/telegram-media-cache/`
(для других библиотек — внутри их каталога данных). Повторная подготовка сначала
берёт файлы из кэша; изменения исходника или параметров обработки требуют новой
подготовки. Отмена и перезапуск сохраняют готовый кэш. После подтверждённой
публикации соответствующие файлы удаляются из кэша; при ошибке они сохраняются.
Оригиналы не изменяются. В проверке постов отображаются миниатюры из существующих
превью, исходный и выходной формат, размер подготовленного файла и известная длительность видео.

«Остановить подготовку» сохраняет полностью готовые посты доступными для отправки.
Незавершённые посты отмечаются как «Не подготовлен» и не отправляются частично.
«Отправить готовые по порядку» останавливается перед первым неготовым постом или
ошибкой; готовые посты после него можно выбрать явно. Обычная подготовка
неотправленных учитывает изменения черновиков и использует дисковый кэш.

При остановке отправки или сетевой ошибке подготовленная очередь остаётся доступной:
можно повторить отправку выбранных готовых постов или продолжить по порядку без новой
подготовки. Подтверждённые публикации пропускаются, статусы и счётчик обновляются после
каждого поста. При неизвестном результате сначала проверьте канал и отметьте результат
в карточке поста. Перезапуск сервера требует повторной подготовки с кэшем.
Между запросами выдерживается интервал не менее секунды с учётом времени запроса;
ответ Telegram с `retry_after` может потребовать более долгой паузы.

При открытии окна Telegram список постов и счётчики восстанавливаются с диска без
сетевых запросов: видно отправленные посты, готовые файлы в кэше и неподготовленные.
«Готов в кэше» означает, что можно сразу выбрать отправку: сервер проверит канал,
подпись и готовые файлы без повторного преобразования. При ошибке проверки публикация не начинается.
Ссылки на публикации и подтверждение неизвестного результата находятся прямо в
карточках постов. Галочка «Скрыть отправленные» скрывает их без удаления журнала.

Название отправленного поста открывает публикацию в Telegram. Миниатюра с доступным
подготовленным файлом открывает итоговый JPEG или MP4 в полноэкранном просмотрщике
без изменения размера на сервере. Стрелки переключают файлы поста, Esc закрывает просмотр.
Если копия удалена после публикации, миниатюра открывает пост в Telegram; если до неё —
показывается размытое превью с надписью «Отправленный файл удалён».
